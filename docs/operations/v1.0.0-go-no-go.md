## B. Required Final Checks Before Tagging

Run all of these on the exact commit that will be tagged `v1.0.0`.
All must pass. No exceptions.

```bash
# 1. Working tree must be clean
git status

# 2. Pull latest — no surprises before tagging
git pull --ff-only

# 3. Tests
go test ./...
go build ./...
go test -race ./internal/downloader
go test -race ./internal/tui

# 4. Quality gates
make lint
make security
goreleaser check

# 5. Full rc-check (includes govulncheck, gosec, goreleaser check, race tests)
make rc-check

# 6. Release artifact validation (local snapshot, no publish)
make release-check

# 7. Sanity checks
git diff --check
sh -n scripts/manual-qa-server.sh
```

All commands must exit 0 before the tag is created.

Expected results:
- `go test ./...` — all packages pass.
- `go build ./...` — no errors.
- Race tests — pass.
- `make lint` — 0 issues.
- `make security` — no vulnerabilities, Issues: 0.
- `goreleaser check` — configuration valid.
- `make rc-check` — PASS.
- `make release-check` — PASS, snapshot artifacts generated.
- `git diff --check` — no whitespace issues.
- `sh -n scripts/manual-qa-server.sh` — syntax valid.

## D. Asset Decision

The asset decision is final. The v1.0.0 GitHub release **will include** compiled
binary assets. Source-only is not acceptable for the public stable release.

Assets to attach:

| File | Platform |
|------|----------|
| `daryaft_linux_amd64.tar.gz` | Linux x86-64 |
| `daryaft_linux_arm64.tar.gz` | Linux ARM64 |
| `daryaft_darwin_amd64.tar.gz` | macOS x86-64 |
| `daryaft_darwin_arm64.tar.gz` | macOS ARM64 (Apple Silicon) |
| `checksums.txt` | SHA-256 checksums for all archives |

**Not included at v1.0.0:**
- Windows binaries (not officially supported).
- Package manager packages (Homebrew, deb, rpm, Arch) — post-1.0.
- Signed checksums — post-1.0.

The release build and upload process is documented in
[v1.0.0 Release Assets](release-assets.md) and
[v1.0.0 Release Plan](v1.0.0-release-plan.md).

## E. Go / No-Go Decision

### GO if:
- All final checks in Section B pass with exit 0.
- No blocker bugs are known from RC validation or last-minute testing.
- Release notes reviewed and accurate (Section C complete).
- Binary assets ready to upload (Section D).
- Working tree is clean.

### NO-GO if any of the following:
- Any quality or security check fails.
- `govulncheck` reports a vulnerability.
- `gosec` reports an issue.
- `make rc-check` fails.
- `make release-check` fails or produces unexpected artifacts.
- A blocker bug is identified that has not been fixed.
- Release notes are inaccurate or incomplete.
- Assets are missing, broken, or fail checksum verification.
- Working tree is not clean at tag time.

### Fix-forward policy:
- If a NO-GO condition is found after v1.0.0 is tagged and published, prefer
  `v1.0.1` over retagging or deleting v1.0.0. Do not retag a published release
  unless it contains a critical security issue.
- If a NO-GO condition is found before tagging, fix on `main`, confirm all
  checks pass, then re-evaluate this checklist.
