# Daryaft v1.10.0 — Config Persistence Safe Core

## Status

Implemented. Shipped in v1.10.0.

## Background

The config system (YAML format, all config commands, env variable layer) shipped
in earlier releases. v1.10.0 closes three specific gaps: `user_agent` and
`timeout` config keys with matching env variables, a `--timeout` download flag,
and a global `--config <path>` flag for explicit config file selection.

## In Scope

- `user_agent` config key — default User-Agent for downloads
- `DARYAFT_USER_AGENT` environment variable override
- `timeout` config key — overall HTTP request timeout (Go duration string)
- `DARYAFT_TIMEOUT` environment variable override
- `--timeout` download flag — per-invocation timeout override
- Global `--config <path>` persistent flag — explicit config file selection
- Tests for all new keys, env vars, flags, and override precedence
- Documentation updates

## Out of Scope

- Credential storage (username, password, token, secret, api_key)
- Authorization header persistence
- Cookie or session persistence
- Proxy URL persistence
- Arbitrary header persistence
- Config profiles or include/import
- Remote config
- TUI config editor or interactive config editor
- Auto-update

## Precedence

```text
CLI flags > DARYAFT_* environment variables > config file > built-in defaults
```

`--user-agent` and `DARYAFT_USER_AGENT` override config `user_agent`.
`--timeout` and `DARYAFT_TIMEOUT` override config `timeout`.
`--config <path>` redirects all config reads for the current invocation.

## Behavior Changes

- `daryaft config keys` now lists `user_agent` and `timeout`.
- `daryaft config show` now includes `user_agent` and `timeout` fields.
- `daryaft config set user_agent <value>` / `daryaft config get user_agent` work.
- `daryaft config set timeout <duration>` / `daryaft config get timeout` work.
- `daryaft download --timeout 30s` sets an overall HTTP client timeout.
- `daryaft --config /path/to/config.yaml <subcommand>` uses the specified file.
- Missing default config: non-error (unchanged behavior).
- Missing explicit `--config` path: error.
- `daryaft --config /new.yaml config init`: creates the file at the given path.

## Security Policy

The strict YAML decoder (`KnownFields: true`) rejects unknown keys. Attempting
to write `username`, `password`, `authorization`, `cookie`, or similar fields
to the config file produces a parse error. `DARYAFT_USERNAME` and
`DARYAFT_PASSWORD` remain the only credential mechanism and are handled outside
`internal/config` — they are never persisted.

## Quality Gates


## Known Limitations

- `proxy` and `headers` are intentionally not persisted in v1.10.0.
- `timeout` applies to `http.Client.Timeout` (overall request deadline);
  transport-level timeouts (dial, TLS, response header) are separate and
  remain at their hardcoded defaults.
- No config profiles.
- No TUI config editor.
- No auto-update.
