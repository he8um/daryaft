# Daryaft v1.11.0 — TUI Config Awareness

## Status

Implementation scope.

## In scope

- Read-only TUI Settings screen
- Config path display
- Config loaded/defaults display
- Safe effective config values display: `download_dir`, `retries`, `resume`, `no_color`, `no_tui`, `theme`, `animations`, `hyperlinks`, `user_agent`, `timeout`
- `c` shortcut from the TUI home screen to open Settings
- Tests for rendering, navigation, no-color mode, and config field display
- Documentation and manual QA updates

## Out of scope

- TUI config editing of any kind
- Config set/reset from TUI
- Credential entry in TUI
- Secret display (passwords, tokens, auth headers, cookies, proxy URLs)
- Auth header, cookie, session, or proxy persistence
- Arbitrary header persistence
- Config profiles or profile switching
- Live config reload
- Remote config or config sync
- TUI theme editor
- Auto-update or self-update
- Package-manager automation
- Homebrew formula changes
- Windows support

## Security policy

The Settings screen displays only safe non-secret config values. It must not display
credentials, tokens, cookies, auth headers, proxy values, or credential environment
variables. The strict YAML decoder already rejects secret keys from config files; the
Settings screen extends that boundary into the TUI.
