# Daryaft v1.13.0 — TUI HTTP Options Wiring

## Status

Implementation scope.

## Current state

- Latest stable: v1.12.0
- Current development: 1.13.0-dev
- v1.12.0 shipped TUI input defaults preview.
- `user_agent` and `timeout` are visible in TUI Settings/defaults preview.
- Actual TUI downloads do not yet use those values.

## Problem

The TUI currently displays `user_agent` and `timeout`, but actual TUI download execution does not honor them. This creates a mismatch between what the TUI shows and what it actually does.

## Goal

Wire existing safe HTTP options into TUI download execution:

- `user_agent`
- `timeout`

No new config keys.

No new credential handling.

No auth/proxy/header input.

## In scope

- Pass configured `user_agent` into TUI download execution.
- Pass configured `timeout` into TUI download execution.
- Preserve existing CLI behavior.
- Preserve existing config/env/CLI precedence.
- Preserve TUI Settings/defaults preview behavior.
- Add tests proving TUI uses `user_agent`.
- Add tests proving TUI uses `timeout`.
- Add regression tests for empty/default values.
- Update usage/configuration/manual QA docs.
- Update CHANGELOG `[Unreleased]`.

## Out of scope

- New config keys.
- Config editor.
- TUI credential input.
- Authorization header input.
- Cookie/session persistence.
- Proxy input or proxy persistence.
- Arbitrary header input.
- Queue/session persistence.
- Retry policy changes.
- Checksum behavior changes.
- Auto-update.
- Release work.
- Homebrew updates.
- Windows-specific support.

## Proposed implementation direction

The minimal implementation should reuse existing HTTP option infrastructure.

Expected direction:

1. Ensure TUI plan creation can carry `download.Options.HTTPOptions`.
2. Pass `m.userAgent` into `download.Options.HTTPOptions.UserAgent`.
3. Parse/apply `m.timeout` consistently with CLI behavior.
4. Update default execution runner to use `httpopts.NewClient(...)` or equivalent existing helper.
5. Instantiate downloader with `downloader.NewWithOptions(...)` instead of default zero-option downloader where needed.
6. Keep empty `userAgent` and empty `timeout` as default behavior.
7. Do not introduce credential/auth/proxy/header input.

## Security policy

- `user_agent` is a safe displayable string.
- `timeout` is a safe duration string.
- Do not display or persist credentials.
- Do not display or persist tokens.
- Do not display or persist Authorization headers.
- Do not display or persist cookies.
- Do not display or persist proxy secrets.
- `DARYAFT_USERNAME` and `DARYAFT_PASSWORD` remain CLI/env behavior only.
- TUI must not add credential input.

## Test plan

Required tests should cover:

- TUI model receives `UserAgent` and `Timeout`.
- URL download flow passes `UserAgent` into HTTP/downloader options.
- URL download flow passes `Timeout` into HTTP client or execution options.
- File download flow passes `UserAgent`.
- File download flow passes `Timeout`.
- Empty `UserAgent` preserves default behavior.
- Empty `Timeout` preserves default behavior.
- Invalid timeout handling follows existing config/CLI validation behavior.
- Settings screen still displays values.
- Defaults preview still displays values.
- No secret-like strings appear in TUI output.
- CLI user-agent/timeout behavior remains unchanged.
