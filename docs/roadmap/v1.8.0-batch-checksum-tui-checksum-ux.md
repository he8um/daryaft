# Daryaft v1.8.0 — Batch Checksum Support + TUI Checksum Status

## Scope

v1.8.0 extends checksum verification from single-target downloads to batch
downloads via a checksum manifest file, and surfaces the resulting checksum
status in the TUI queue and summary.

### In scope

- `--checksum-file <path>` flag on `daryaft download` and root URL mode.
- Checksum manifest parser (`checksum.ParseManifestFile`) with line-numbered
  validation errors, comment/blank-line handling, and duplicate-URL rejection.
- Manifest format `<algorithm>:<hex> <url>`, one entry per line.
- Exact URL matching between manifest entries and planned download targets.
- Per-target checksum mapping in `download.Plan` (`TargetChecksums`).
- Unified checksum verification inside `downloader.DownloadBatchContext` for both
  single-target (`Plan.Checksum`) and per-target (`Plan.TargetChecksums`) cases.
- Checksum mismatch counted as a failed batch item; file left in place.
- `Checksum verified: N` count in batch summaries.
- TUI queue and summary checksum status: `Checksum OK`, `Checksum Failed`.
- `--checksum` and `--checksum-file` mutual exclusion.
- Full test coverage: unit, integration via `httptest.Server`, and manual QA.

### Out of scope

- Checksum manifest auto-discovery.
- GNU `sha256sum`-style file compatibility.
- PGP/GPG/signature/attestation/SBOM verification.
- Per-URL output overrides in the manifest.
- TUI checksum input forms for batch downloads.
- Live "verifying" progress events in the TUI.
- URL normalization or canonicalization for matching.
- Config persistence, auto-update, OAuth, credential storage, `.netrc`, SOCKS5.
- Concurrent batch downloads.
- GoReleaser Homebrew publishing.

## Data model

- `download.Options.ChecksumFile string` — raw flag value.
- `download.Plan.TargetChecksums map[string]checksum.Spec` — per-URL checksum.
- `download.Plan.HasChecksumFile bool` — a checksum file was supplied.
- `downloader.BatchItemResult.ChecksumStatus string` — `""`, `verified`, `failed`.
- `downloader.BatchResult.ChecksumVerified int` — count of verified items.
- `Plan.URLs` remains a flat `[]string`; no per-target struct in this version.

- Manual smoke: matching batch manifest, mismatched batch manifest, dry-run.

## Known limitations

- Checksum file URL matching is exact; no normalization.
- No GNU `sha256sum` compatibility.
- No checksum auto-discovery.
- No signature/PGP/attestation verification.
- No TUI batch checksum input form.
- No live "verifying" status in the TUI.
- Checksum verification confirms integrity against a known digest, not publisher
  authenticity.
