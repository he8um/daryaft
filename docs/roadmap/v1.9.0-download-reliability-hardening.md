# Daryaft v1.9.0 — Download Retry/Resume Reliability Hardening

## Status

Implementation scope. The downloader core already implemented retry
classification, exponential backoff, resume with HTTP Range, `206`/`200`/`416`
handling, ETag/Last-Modified change detection, and cancellation. This release
closes specific reliability gaps and locks existing invariants with tests and
docs rather than rebuilding the core.

## Scope

v1.9.0 hardens existing download retry and resume behavior. It is intentionally
small: one retry-classification gap, one proactive resume guard, and a
test/doc pass over edge cases.

### In scope

- HTTP `408 Request Timeout` added to retryable download responses.
- Retry-classification test coverage for retryable and non-retryable HTTP
  statuses (`408`, `429`, `500`, `502`, `503`, `504` retryable; `400`, `401`,
  `403`, `404`, `410` non-retryable).
- Deterministic integration test for `408` followed by success.
- Proactive partial-overflow resume guard: when the local partial file is
  larger than or equal to the known remote total size, restart from byte `0`
  instead of appending past the end of the remote file.
- Resume-safety tests for oversized partial files and missing/corrupt resume
  sidecar metadata.
- Verification that cancellation around checksum verification cannot be
  misclassified as a generic failure (no code change required; documented).
- Retry/resume documentation hardening.

### Out of scope

- `Retry-After` response-header support.
- Treating `416 Requested Range Not Satisfiable` as proof the partial file is
  already complete (`416` always restarts).
- New retry-policy flags or new CLI output modes.
- New downloader events, TUI statuses, or `BatchResult` counters.
- Concurrent batch downloads.
- Config persistence, auto-update, checksum auto-discovery.
- Signature/PGP/attestation verification, GNU `sha256sum` compatibility.
- OAuth, token manager, cookie jar, credential storage, `.netrc`, SOCKS5.
- Package-manager automation, release automation, Homebrew changes.
- Windows-specific support.

## Behavior changes

- `408` now triggers the standard retry path with exponential backoff instead
  of failing immediately.
- A `206` response whose known total is at or below the resume offset now
  restarts from byte `0` with the message
  `Partial file is larger than remote file; restarting download`, rather than
  appending.
- Missing or corrupt sidecar metadata continues to restart safely; this is now
  locked by tests.

## Quality gates

- `go test ./...` passes.
- `go build ./...` passes.
- `go test -race ./internal/downloader` passes.
- `go test -race ./internal/tui` passes.
- `make lint` passes.
- `make security` passes.
- `goreleaser check` passes.
- `make rc-check` passes.

## Known limitations

- `Retry-After` is not honored yet; `429` uses the standard exponential
  backoff schedule.
- `416` always restarts from byte `0` instead of treating the partial file as
  complete.
- No concurrent batch downloads.
- No config persistence.
- No auto-update.
